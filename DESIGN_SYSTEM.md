# Design System & Data Rules — Marketing Intelligence Hub

Единые правила для ВСЕХ страниц и компонентов. Любой новый экран, блок или
метрика строится по этому файлу. Отклонение = баг.

## 1. Данные — только настоящие

- **Никаких fake/demo данных.** Ни захардкоженных процентов (`change={0.05}`),
  ни выдуманных значений, ни нулей вместо отсутствующих данных.
- Метрика есть и равна 0 → показываем `0`.
- Метрика недоступна в подключённых API → плитка-заглушка «Недоступно»
  (компактная, приглушённая — см. `KpiTile unavailable`).
- Нет данных за период → явное сообщение
  «За вибраний період … не має витрат, кліків або показів», не тихий ноль.
- Google Ads MCC **9687257696 — только менеджер**, никогда не источник метрик.
  Метрики: EMET 6768706978 + Esse 3513546897 (прямой доступ, не через MCC).

## 2. Один источник данных для страниц — `/api/overview`

- Страницы получают данные ОДНИМ запросом: `/api/overview?rangeKey=...`.
- Endpoint автообнаруживает источники из `data/warehouse/<source>/<account>/daily/`
  — новый подключённый источник появляется на страницах без правок UI.
- Ответ содержит `previous` (тот же период длиной назад) — по консолидации,
  по каждому источнику и по каждому аккаунту.
- Пайплайн данных: sync (raw) → normalize → daily warehouse → `/api/overview`.
  UI никогда не читает raw/normalized напрямую.

## 3. Период — единый селектор

Правило общее для ВСЕХ продуктов экосистемы: Marketing Intelligence Hub, PR
Intelligence Hub и любого следующего.

- Верхний правый селектор дат управляет ВСЕМИ страницами, вкладками,
  графиками и KPI. `selectedDateRange` → `dateRangeToFileKey()` → `rangeKey`.
- Запрещено хардкодить «последние 30 дней» или показывать данные одного
  периода под видом другого.
- **Второго селектора периода на странице быть не может.** Свой набор кнопок
  «7 / 14 / 30 дней» в теле страницы — это два разных ответа на вопрос «за
  какие дни эти числа» на одном экране: человек читает верхний селектор, а
  числа считаются по нижнему. Нужны свои пресеты — их место в шапке.
- **Блок, на который период НЕ действует, обязан сказать об этом словами** —
  строкой под заголовком страницы: что слушается периода, а что является
  снимком на дату. Молчание читается как «период применён ко всему», и это
  неправда. Касается снимков складов, справочников, реестров.
- Если период странице не нужен вовсе (Документы, Команда, Настройки), слот
  периода в шапке говорит «не зависит от периода» — пустоты там не бывает.

История правила: 24.08.2026 на странице CRM Metriverra под шапкой жил свой
«Период инсайтов» с собственными пресетами, и верх экрана противоречил низу.

## 3b. Боковая колонка: узкий вид на компьютере

Решение владельца 24.08.2026: на широком экране колонка занимает 256 px,
которые нужнее таблицам и графикам. Правило общее для всех продуктов.

- Колонка сворачивается **только на компьютере** (≥1024 px) до 76 px: остаются
  значки, название раздела показывается подсказкой при наведении. На телефоне
  она и так выезжает поверх страницы — там узкого вида НЕТ, и признак «узко»
  не должен включаться шириной вообще (иначе свёрнутая на компьютере колонка
  приезжает ужатой на телефон).
- Кнопка сворачивания живёт **значком в шапке колонки**, в одной строке с
  названием продукта: отдельная строка сбивает ритм между брендом и разделами.
  Значок — панель со стрелкой, а не голая стрелка: голая читается как «назад».
- В узком виде ОСТАЮТСЯ: смена приложения (значком), счётчики разделов, выход.
  ПРЯЧУТСЯ: название продукта, подписи разделов, заголовки групп, «Смотреть
  как» — от ролей остались бы обрубки слов.
- Выбор периода, кабинета и языка живут в верхней полосе и от ширины колонки не
  зависят вовсе.
- Состояние запоминается между заходами; отступ содержимого едет вместе с
  колонкой.
- **Механизм один на все продукты, а не «такой же».** Кнопка живёт в ядре
  (`@verra/core/ui/RailToggle`) вместе с памятью о выборе; узкий вид делают
  правила пакета по `data-rail` на `<html>`. Продукт только вешает классы:
  `.rail-shell`, `.rail-head`, `.rail-brand`, `.rail-item`, `.rail-label`,
  `.rail-caret`, `.rail-foot`, `.rail-offset`, а также `.rail-icon-only` /
  `.rail-wide-only` там, где значок заменяет подпись. Считать ширину в React
  НЕЛЬЗЯ: две копии одной механики расходятся на первой же правке — так и
  вышло 24.08.2026, когда в одном хабе кнопка стояла в шапке, а в другом
  накладывалась поверх неё.

## 3c. «Техническое» — один блок на все приложения

Требование владельца 24.08.2026: «тех часть тоже точно такая же на двоих».

- Состав, порядок строк, значки и права живут в ядре
  (`@verra/core/ui/tech-nav`): «Что нового» · «Настройки» · «Документы»
  (админам) · «Обратная связь» · «Команда» (админам) · «Блог» (владельцу
  платформы). Продукт подставляет свои адреса, названия и счётчики.
- Блок **свёрнут по умолчанию** (настраивают редко), выбор человека
  запоминается, заход на его страницу раскрывает блок — но только если человек
  сам его не свернул. Счётчик нового виден на заголовке, пока блок закрыт.
- Раздел, для которого продукт не дал адрес, просто не показывается: строки
  «появится позже» в меню быть не должно.

## 3d. Таблицы: первый столбец закреплён — правило, а не привычка

Замечание владельца 24.08.2026 (повторное): на телефоне первый столбец таблицы
обязан оставаться на месте, иначе цифры уезжают от имени, к которому относятся.

- Правило действует на **каждую** таблицу обоих продуктов **само**. Продукту
  ничего не нужно помнить: компонент пакета `react/TableRules` монтируется один
  раз в оболочке кабинета, находит у таблицы настоящего прокручиваемого предка
  (по вычисленному `overflow-x`, а не по классу), помечает его `.table-scroll`,
  а таблицу — `.table-pinned`. Обёртки нет вовсе — он делает прокручиваемым
  ближайшего родителя.
- **`border-collapse: collapse` в таблицах запрещён**: Safari на iPhone в такой
  таблице не закрепляет ячейки вообще. Пакет сам переводит помеченные таблицы на
  `border-collapse: separate; border-spacing: 0` — границы у нас и так рисуют
  ячейки.
- Ширина закреплённого столбца — **по содержимому** (`min-width: min-content`),
  но не больше 58vw / 360 px. Фиксированной ширины здесь быть не может: она
  либо режет длинное имя в буквенную кашу («Кр/ос/с-/сет/ь»), либо раздувает
  короткую подпись («Пн» в тепловой карте «день × час») на пол-экрана.
- Длинное имя показывается в две строки, переносится ПО СЛОВАМ и раскрывается
  целиком по касанию — тот же компонент.
- Проверка в продуктах — тестом-стражем: `<table>` без прокручиваемой обёртки
  роняет проверку, чтобы следующая таблица не приехала снова уехавшей.

## 3e. Переходы между разделами

- Ссылки боковой колонки — только `@verra/core/ui/NavLink`, не `next/link`
  напрямую. На компьютере он предзагружает раздел заранее (сеть стабильная,
  переход становится мгновенным), на телефоне — НЕ предзагружает: там
  приложение тянуло сразу несколько соседних разделов «про запас», часть
  соединений обрывалась, и браузер показывал свою заставку вместо страницы
  (замечание владельца 24.08.2026, подтверждено журналом обращений сервера).
- Поведение перехода обязано совпадать во всех приложениях холдинга — поэтому
  компонент общий, а не правка в каждом продукте.

## 4. Сравнения «пор. з попереднім періодом» — везде одинаково

- Каждая живая KPI-плитка показывает сравнение с предыдущим равным периодом
  (`overview.previous`). Три честных состояния `KpiTile`:
  - `change={number}` → цветной бейдж `+12,3% / -5,1%`
  - `change={null}` → «Немає даних для порівняння» (курсив)
  - `change={undefined}` → без футера (источник не подключён)
- Запрещён фейковый «+0.0%» и выдуманные changeLabel.

## 4b. Доверие к данным (обязательные правила)

- **Часовой пояс**: все датовые границы — Europe/Kyiv
  (`toLocaleDateString('en-CA', { timeZone: 'Europe/Kyiv' })`), не UTC.
- **Страж покрытия**: Δ к предыдущему периоду показывается только если
  предыдущее окно покрыто данными ≥70% (`coveredDays / previousRange.days`),
  иначе «Немає даних для порівняння».
- **Свежесть**: `/api/overview.freshness` — время последнего синка каждого
  источника; при >26 часов — красное предупреждение в статусе источников.
- **Приблизительные метрики** помечаются `≈` (например, users, суммированные
  по дням) с объяснением в глоссарии.
- **Окна данных в подписях**: если блок живёт не по выбранному периоду
  (окно синка GSC-агрегатов, GA4-доход 365 дн.), даты окна указываются
  в subtitle явно.
- **Рост расходов — нейтральный** серый бейдж (`changeNeutral`), не зелёный.

## 5. Компоненты — только эти

| Роль | Компонент |
|---|---|
| Контейнер блока | `BentoCard` (`src/components/dashboard/BentoCard.tsx`) |
| Заголовок группы KPI | `GroupHeader` (акцентная планка + линия) |
| Метрика | `KpiTile` (`src/components/dashboard/KpiTile.tsx`) |
| График тренда | `TrendChart` |
| Пояснение таблицы/графика | `DataExplanation` (`src/components/data/DataExplanation.tsx`) |

Самодельные карточки метрик запрещены. Нужен новый вариант — расширяем `KpiTile`.

### 5a2. Длинные таблицы — топ-15 + «Показать все»

Любая таблица, которая может вырасти больше 15 строк, обязана использовать
`useTableRows()` + `<TableRowsFooter>` (`src/components/ui/useTableRows.tsx`):
по умолчанию видно 15 строк, кнопка раскрывает до 100. Свои `.slice(0, N)`
по месту запрещены — иначе страницы расходятся в поведении.

Правила компонента (они и есть причина его существования):
- если строк ≤15, подвал не рендерится вовсе — короткие таблицы не засоряются;
- обрезка **никогда не молчит**: подпись «Показано N по расходам из M» видна и
  в свёрнутом, и в раскрытом виде;
- смена набора строк (фильтр, вид, окно) сворачивает таблицу обратно — иначе
  после переключения виден хвост чужого списка.

### 5b. Пояснение данных — обязательно

Каждая аналитическая таблица и каждый график заканчиваются компонентом
`DataExplanation`. Он получает серверный `sourceContext` из `/api/overview` и
показывает четыре проверяемых факта: что вошло в расчёт, что подключено без
строк за окно, что не подключено и не учтено, какое окно/фильтр применён.
Если сохранённые строки используются после отключения доступа, это выводится
отдельным предупреждением. `insight` строится только чистой детерминированной
функцией из показанных значений; LLM-текст и статические заглушки запрещены.

### 5c. Выпадающие списки — единая ширина

Все дропдауны — только `LiquidSelect` (одиночный выбор) или `MultiSelect`
(чекбоксы, `selected: string[]`, `[]` = «все»). Оба обязаны соблюдать правило
**одной ширины**: кнопка-триггер и выпадающее меню имеют **ровно одну ширину** —
ширину самого длинного пункта. Меню НИКОГДА не шире и не уже своей кнопки.
Реализовано хуком `useDropdownWidth(options)` (`src/components/ui/dropdownWidth.tsx`):
он замеряет пункты в скрытом «пробнике» и отдаёт `width` для кнопки и меню + `probe`
для рендера. Свою логику ширины у дропдаунов не писать — только этот хук.

### 5d. Выбор кабинетов у многоаккаунтных каналов — `AccountPicker`

Каждый канал (Google Ads, GA4, Merchant, Search Console, Meta) может иметь
несколько подключённых кабинетов (слоты по тарифу). На аналитической странице
канала выбор кабинета — только через **`AccountPicker`**
(`src/components/ui/AccountPicker.tsx`, поверх `MultiSelect`):

- один и тот же вид и поведение на ВСЕХ каналах и проектах;
- `selected: string[]`, `[]` = «Все кабинеты» (сводно); можно выбрать любое
  подмножество (в т.ч. 2 из 3);
- при 0–1 кабинете компонент **не рендерится** (выбора нет — одноаккаунтные
  тенанты видят страницу как раньше);
- список кабинетов — data-driven: кабинет появляется в дропдауне **после первого
  синка** (когда у него есть данные), автоматически, без правок кода.

Самодельные переключатели кабинетов (табы, отдельные `LiquidSelect`, галочки)
на каналах запрещены — только `AccountPicker`.

## 6. Форматирование чисел — украинский рынок

Только через `src/lib/utils/format.ts`:
- `formatNumber(20328.45)` → `20 328,45` (пробел — тысячи, запятая — десятые)
- `formatCurrency(4830.27)` → `₴4 830,27`
- `formatDecimal(11.47, 2)` → `11,47`
- **Деньги (доход, оборот, выручка, расходы, средний чек) показываем ЦЕЛЫМИ,
  без копеек:** `₴${formatNumber(Math.round(v))}` → `₴1 190 609`. Копейки в
  крупных денежных суммах не нужны и ломают выравнивание плиток. Проценты, ROAS,
  MER, коэффициенты — с десятыми, как обычно.
- ROAS — множитель `11,47x`, НЕ проценты.
- Даты: `15 чер`, тултип `пн, 15 чер 2026`.
- В компонентах запрещены `toFixed()`, `toLocaleString('en-US')`, `Intl` напрямую.
- Цифры в плитках/таблицах — класс `tabular-nums`.

## 5e. Кнопки: три семьи, и ни одной «по вкусу страницы»

**Внешность кнопки живёт в `src/app/globals.css`, а
НЕ в разметке.** В компоненте задаются только размер, отступы и скругление;
заливка, рамка и цвет подписи приходят из класса семьи:

| Класс | Смысл |
|---|---|
| `.btn-primary` | действие: тёмная заливка, светлый текст |
| `.btn-quiet` | второстепенное: рамка и лёгкий фон, **видна без наведения** |
| `.btn-danger` | необратимое (удалить): красная заливка — предупреждение, не украшение |

`bg-*`, `border`, `text-white/brand-bg/band-ink` в кнопках ЗАПРЕЩЕНЫ. Это
стережёт `tests/button-families.test.ts`: он разбирает каждый тег `<button>`,
включая классы внутри условий, и падает на любой кнопке, которая красит себя
сама.

Зачем так: 20.08.2026 пересчёт показал **23 разных внешности кнопок** — никто
их не проектировал, каждая новая красилась по месту. Человек читает разный вид
как разное поведение. Списком это чинить бессмысленно: через месяц набежит
новый десяток, поэтому правило держит тест, а не память.

Вкладки (`.tabs-folder`) — не кнопки: у них своя роль и свой вид, см. 5d.

**Геометрия кнопки** — канон `.btn` (добавляется к семье: `btn btn-primary`):
отступы, радиус, высота — один раз на экосистему. Опционален для старой
разметки, обязателен для новой.

**«Выбрано»** — состояние, не украшение: `aria-pressed`/`aria-selected` на
`.btn-quiet` даёт вид btn-primary (контраст, не рельеф — тень пропадает на
плохом мониторе). Отдельных классов выбранности не заводить.

## 5f. Поля ввода: одно поле — класс `.field`

**Поле в проекте одно.** 21.08.2026 пересчёт показал 18 разных внешностей у
72 полей: фон от белого/40 до белого/80, скругление от 6 до 16 пикселей —
каждая форма одевала поля сама. Теперь внешность (фон, рамка, скругление,
фокус, placeholder, invalid, disabled) живёт в классе `.field` в
`src/app/globals.css`; разметка задаёт только ширину и ступень текста.

Осознанное исключение — иерархия бюджета (`.inp-lvl0…2`, `.inp-auto`): там
рамка **несёт смысл** (уровень плана), это не вкус страницы.

Стережёт `tests/field-look.test.ts`: любое текстовое поле с собственной
заливкой/рамкой/скруглением мимо `.field` роняет тест. Там же — запрет сырых
цветовых шкал Tailwind (`text-red-700` и подобных): цвет берётся из палитры
по имени, иначе он не подчиняется ни смене палитры, ни теме.

## 5g. Пилюли состояний: пять семей `.pill-*`

Короткая цветная метка (статус, счётчик, категория) — это `.pill` + семья по
смыслу: `.pill-good` / `.pill-warn` / `.pill-bad` / `.pill-info` /
`.pill-quiet`; счётчик непрочитанного — `.pill-count` (тревожная заливка,
круглая форма). Цвет пилюли — сообщение, а не украшение. Собственные
`rounded-full bg-*` бейджи по месту не заводить. Точки-индикаторы
(`w-2 h-2 rounded-full`) и полосы прогресса пилюлями не считаются — это не
текстовые метки.

## 5h. Тени и свечения — именами, не значениями

`shadow-[…rgba(48,40,37,…)]` в разметке — это цвет, вписанный числами: смена
палитры его не трогает (именно так старый тёплый ink пережил перекраску в
тенях и осях графиков). Тень берётся именем из `globals.css`:
`.shadow-float` (подсказки/панели поверх), `.shadow-pick` (выбранный пункт
списка), `.inset-soft` (утопленная панель), `.glow-dot-active/warning/error`
(свечение точек статуса), `.auth-card` (карточка входа). Оси, сетка и рамка
подсказок диаграмм — токены `--color-chart-axis/grid/border` через `COLOR`.
Числовые `rgb()/rgba()/hsl()/oklch()` в tsx запрещены сторожем
(`tests/color-tokens.test.ts`); ссылка `rgb(var(--…-rgb) / …)` — разрешена.

## 5i. Модальное окно: компонент `Modal` (+ `.modal-scrim` / `.modal-panel`)

Каркас модального окна — компонент `src/components/ui/Modal.tsx`: портал
поверх всего, закрытие по Escape и по клику в пелену. Внешность — классы
`.modal-scrim` и `.modal-panel` в globals.css. Свои затемнения и свои
`<dialog>` не собирать: до 21.08.2026 их было два разных, теперь один.

## 5j. Где CSS-класс, а где компонент — правило разделения

**Внешность живёт в CSS-классе, поведение — в компоненте. Ни один элемент не
живёт в двух реализациях.**

- Есть только внешность (кнопка, поле, пилюля, тень, ступень текста) —
  ЭТО КЛАСС в globals.css. React-обёртка без поведения — лишний слой:
  её пришлось бы импортировать в 90 файлов ради того же результата.
- Есть поведение (открыть/закрыть, выбор, сортировка, запоминание) —
  ЭТО ОДИН КОМПОНЕНТ в `src/components/ui/`, и разметку из него не
  копируют руками. Найдено и вычищено 21.08.2026: три самодельных ряда
  закладок при живом `Tabs`, два каркаса модального окна, четыре спиннера.

Реестр компонентов с поведением: `Tabs`, `Modal`, `LiquidSelect` (один
выбор), `MultiSelect` (несколько), `AccountPicker` (кабинеты, построен НА
MultiSelect — не копия), `HoverTip`, `InfoHint`, `LoadError`, `SortableTh` +
`useSort`, `TableRowsFooter` + `useTableRows`, `TableExportButtons`,
`DateRangePicker` (календарь — уникальный контрол), `BentoCard`, `KpiTile` /
`ChangeBadge` / `GroupHeader`, `Icon`. Новый выпадающий список, тултип или
окно начинаются с вопроса «какой из этих компонентов это уже умеет», а не с
пустого div.

## 5e-bis. Состояния — те же кнопки, а не другие

Кнопка в проекте одна — `.glass-btn`. Разными бывают только состояния:

- **обычная** — плотная заливка (`bg-rail` для главного действия);
- **второстепенная** — `.btn-quiet`: рамка и лёгкий фон, **видна без
  наведения**. Кнопка, существующая только при наведении, на телефоне не
  существует вовсе;
- **выключенная** — БЕЗ заливки: контур и приглушённый текст. Прозрачность у
  тёмной кнопки читается как «другая серая кнопка», а не как «нельзя нажать».

Отдельные стили кнопок по месту не заводить: разница должна означать состояние,
а не вкус автора страницы.

## 6b. Размер текста — восемь ступеней, и ни одной сверх

Размер задаётся ТОЛЬКО ступенью шкалы (`src/app/globals.css`, блок в конце):

| Класс | Размер | Роль |
|---|---|---|
| `t-h1` | 28 | заголовок страницы |
| `t-kpi` | 26 | крупные числа |
| `t-h2` | 21 | заголовок блока |
| `t-lead` | 17 | подзаголовок |
| `t-body` | 15 | основной текст |
| `t-data` | 13 | таблицы и плотные данные |
| `t-meta` | 12 | вторичные подписи |
| `t-cap` | 11 | шапки таблиц, метки (700, ЗАГЛАВНЫЕ) |

`text-xs`, `text-sm`, `text-[10px]` и прочие размеры в разметке ЗАПРЕЩЕНЫ.

Зачем: до 20.08.2026 в проекте жило 25 размеров (8; 8,5; 9; 10; 10,5; 11; 12;
13; 17; 21; 22; 23; 26 плюс ступени Tailwind). Шкалы не было — отсюда «прыжки»:
где-то заголовок 28 и сразу 11 (провал втрое, между ними пусто), где-то
заголовок и текст почти неотличимы. Шаг между ступенями ≈1,2.

**Ниже 11 пикселей не опускаемся.** Восемью-девятью были набраны 78 мест — на
телефоне это нечитаемо, и это же примета шаблонной вёрстки.

Исключение одно и осознанное: подписи осей внутри графиков Nivo (задаются
темой библиотеки).

**Проверяется стражем `guards/typography.test.mjs`** (03.09.2026): владелица
снова увидела на одной странице крупный и мелкий текст рядом — новые карточки
были набраны `text-sm`, а таблицы без ступени наследовали браузерные 16px.
Страж роняет сборку за любой размер Tailwind или произвольное значение и за
таблицу, у которой ступень не задана ни на `<table>`, ни на каждой ячейке
(шапки из `SortableTh` ступень несут сами). Правило для таблиц: `t-data` на
`<table>`, `t-cap` на шапках.

**Поля ввода звучат ступенью `.t-data` (13px)** — так же, как подпись рядом с
полем, а не громче её. Задаёт это `.field` в пакете, и переопределять размер
на месте нельзя (страж полей). Про iOS: Safari увеличивает страницу при фокусе
на поле мельче 16px — у нас это выключено `maximumScale: 1` в `viewport` обоих
продуктов, пинч-зум пальцами при этом остаётся.

## 7. Цвет и контраст (WCAG AA)

**Весь цвет продукта живёт в ОДНОМ месте — блоке палитры в `src/app/globals.css`
(`@theme`).** В разметке цветов быть не должно: не `text-[#302825]`, а
`text-neutral-dark`; не `bg-[#8FA99B]/12`, а `bg-tertiary/12`. Это стережёт тест
`tests/color-tokens.test.ts` — он падает на любом `[#…]` в `.tsx`.

Зачем так: до 19.08.2026 около 550 цветов были вписаны прямо в разметку, и смена
палитры означала обход девяноста файлов. По этой же причине была невозможна
тёмная тема — вшитый в класс цвет темой не переключается.

**Цвет в КОДЕ** (графики, SVG, редкие инлайновые стили) берётся из
`src/lib/design/colors.ts`: там нет значений, только ссылки на палитру
(`var(--color-…)`). Браузер подставляет цвет сам — это работает в `fill`,
`stroke`, `stop-color` градиента и в массивах цветов Nivo.

```tsx
import { COLOR, FUNNEL_AD_COLORS } from '../../lib/design/colors';
<NivoTrendChart strokeColor={COLOR.bad} />          // не '#b23b2e'
```

Зачем: до 20.08.2026 цвета диаграмм были вписаны прямо в код страниц, и смена
палитры перекрашивала интерфейс, но не графики — дашборд, воронки и SEO
оставались старого цвета. Единственное исключение — генерация PDF: документ
собирается вне браузера, переменных CSS там нет, и значения остаются
настоящими.

**Публичный сайт** (`src/app/[lang]/marketing.css`) живёт отдельной палитрой в
`.mkt-root` — он не наследует токены приложения. Правило то же: цвет объявляется
в блоке палитры, в стилях используется по имени. Оба блока стережёт один тест.

Тест `tests/color-tokens.test.ts` держит четыре границы: нет `[#…]` в классах,
нет значений цвета в `.tsx` вообще, в `colors.ts` только ссылки, и каждое имя
из `colors.ts` существует в палитре.

**Полупрозрачные слои** (тени, подложки, рамки) берут канал палитры:
`rgb(var(--ink-rgb) / 0.08)`, а не `rgba(48, 40, 37, 0.08)`. Каждому цвету —
СВОЙ канал: свести два разных цвета в один канал значит незаметно перекрасить
интерфейс (поймано при переносе).

Палитра бренда (LUNA, с 20.08.2026) — одна синяя семья от пастели до полуночи:

| Токен | Значение | Роль |
|---|---|---|
| `--color-neutral-dark` | `#011C40` | текст и тёмная оправа |
| `--color-primary-dark` | `#023859` | полосы уровней, нажатые состояния |
| `--color-primary` | `#26658C` | акцент: ссылки, активное, кнопки |
| `--color-primary-light` | `#54ACBF` | ТОЛЬКО заливки (2,5:1 — в текст нельзя) |
| `--color-brand-bg` | `#D8E3E9` | холодная подложка страницы |
| `--color-paper` | `#F6F9FB` | поверхность карточек |

Холодная подложка выбрана не по вкусу: чисто белая карточка рядом с ней
читалась бы тёплой (эффект соседства), поэтому и поверхность холодная.

Зелёный, красный и янтарь **не входят в фирменные** — они означают рост,
потерю и деньги. Именно поэтому акцент синий: любой другой отнял бы у
светофора один из его смыслов (так было с терракотой и лаймом).

**Стекло — только на оправе.** Полупрозрачны боковая панель (`.chrome-rail`),
верхняя полоса, выпадающие списки и модальные окна (`.chrome-glass`). Всё, под
чем лежат цифры, — непрозрачное (`.glass-card`). Под таблицей в двести строк
полупрозрачный фон отнимает контраст, а с ним читаемость.

- Контраст текста ≥ 4.5:1. На фоне `#F4EAE4` для `text-neutral-dark/N`:
  **минимум `/70`** (лейблы), `/75` (вторичный), `/80` (описания).
  `/45`–`/65` — ЗАПРЕЩЕНЫ для текста (только для декоративных иконок).
- Рост = зелёный бейдж `bg-[#8FA99B]/20 text-[#3d5346]`,
  падение = терракотовый `bg-primary/15 text-[#7e5c4c]`. Цвет + стрелка
  (не только цвет).
- **Светофор метрик** (моментальное чтение хорошо/плохо) — токены в
  `globals.css`: `.metric-good` (#3d6b4f), `.metric-warn` (#96691c),
  `.metric-bad` (#b23b2e), + фоновые варианты `.metric-*-bg`. Применять
  там, где у метрики есть общепринятая норма. Утверждённые пороги:
  - Bounce rate (GA4): зелёный <45%, жёлтый 45–65%, красный >65%
  - ROAS: зелёный ≥1x, красный <1x
  - Δ к предыдущему периоду: зелёный ≥0, красный <0
  - Органический CTR: норма 3–6%; небренд-доля SEO: норма 60–75%
  Для метрик «меньше = лучше» (CPA, bounce, позиция, потеря показов)
  использовать `goodWhenDown` в KpiTile.
- Поверхности: `.glass-card` (крупные блоки), `.kpi-tile` (метрики),
  `.kpi-tile-muted` (недоступное, пунктир). Полупрозрачный «туман»
  (`bg-white/10..25` под текстом) запрещён.

## 8. Отступы (8pt-ритм)

- Между крупными блоками страницы: `space-y-8` (32px)
- Между группами KPI внутри блока: `space-y-8`
- Сетка плиток: `gap-4` (16px)
- Внутренние отступы BentoCard: `p-7`; плиток: `p-4`
- Корень каждой страницы: `<div className="space-y-8">`

## 8b. Выравнивание плиток (жёсткое правило)

Во всех плитках, стоящих рядом по горизонтали и вертикали, текст и цифры
выровнены по одним линиям. `KpiTile` реализует фиксированные зоны:
- заголовок — ВСЕГДА резервирует ровно 2 строки (`leading-[13px] min-h-[26px]
  line-clamp-2`), длиннее — обрезается с тултипом;
- значение — фиксированная строка `h-[27px]`, `mt-1.5`;
- футер — стартует с одной y-координаты (`mt-2 min-h-[18px]`).
Кастомные плитки обязаны резервировать зону лейбла так же
(`min-h` кратно строке + `line-clamp`). Цифры не «скачут» между соседями.

## 9a. Система подчинения уровней (обязательна для любой вложенности)

Где есть иерархия элементов (Бюджет: канал→кабинет→бренд; Трафик:
платформа→кабинет→кампании; Настройки: источник→кабинеты и т.п.) —
применяется утверждённая система (владелица, 2026-08-02). Классы в
`globals.css`.

| Уровень | Роль | Поверхность | Типографика |
|---|---|---|---|
| L0 | Канал/раздел | `.lvl-channel` — глубокая терракота #7A5746→#8A6552, светлый текст | 15px / bold |
| L1 | Кабинет/подраздел | `.lvl-cabinet` (тело) + `.lvl-cabinet-head` — глубокий шалфей #5E7367→#6E8478 | 13px / bold + бейдж уровня |
| L2 | Строка (бренд/кампания) | `.lvl-row` — тёплый песок #EADCD2 с терракотовой рамкой, Г-коннектор | 12px / 650, приглушённые цифры |
| L3 | Авто-строка (системная) | `.lvl-row-auto` — серый тон, ПУНКТИР + КУРСИВ | 11px / 600 |

Правила:
1. **Правило четырёх признаков**: соседние уровни различаются минимум
   четырьмя признаками сразу — фон · рамка/планка · размер+вес шрифта ·
   отступ с коннектором. Различие «только отступом» запрещено.
2. **Родитель тяжелее ребёнка**: вниз по дереву — минус 1–2px размера,
   минус вес, минус насыщенность фона. Никогда наоборот.
3. **Линия-происхождение**: ребёнок висит на направляющей родителя —
   `.lvl-lane` (терракотовая, канал→кабинеты) / `.lvl-branch`
   (шалфейная, кабинет→строки).
4. **Своё/системное**: всё, что создала система (авто-строки,
   план-остаток) — пунктир + курсив (`.lvl-row-auto`, `.inp-auto`);
   введённое человеком — сплошное.
5. **Импуты наследуют уровень**: `.inp-lvl0` (светлая рамка + терракотовое
   свечение на тёмной шапке) / `.inp-lvl1` (шалфейная 2px) / `.inp-lvl2`
   (терракотовая 1,5px) / `.inp-auto` (пунктир, read-only).
6. На тёмных шапках уровней светофор метрик — только `.metric-*-inverse`
   (осветлённые: good #D3EBDC / warn #FFE3A8 / bad #FFC9BB); нейтральный
   текст на цветной шапке — не темнее 85% белого.
7. **Мобильная версия** (<768px): БЕЗ ПОДЛОЖЕК ВООБЩЕ. Никаких залитых
   блоков/карточек/полос: уровень читается только толстой цветной планкой
   слева (5px терракота — канал, 5px шалфей — кабинет, 3px — строка,
   пунктир — авто) + типографикой. Текст тёмный (тёмных фонов нет),
   inverse-светофор на мобильном автоматически возвращается к обычным
   цветам, подписи и значения в ячейках — в одну строку.
8. **Плотные таблицы** — тот же язык в табличной форме: родитель-группа =
   полоса `.band-paid`/`.band-free` (те же терракота/шалфей-градиенты),
   строки = `.row-tint-*`, итог группы = `.subtotal-*`, финал = `.band-ink`.
Эталон вёрстки: артефакт «Система подчинения — Metriverra» (сессия 02.08.2026).
Применено: Бюджет (вся иерархия), Настройки (вложенные источники + строки
кабинетов), Команда (участники внутри компании), Дашборд и Трафик (полосы
групп). Новые места с вложенностью обязаны использовать эти классы.

## 9b. Глоссарий метрик (обязательно)

Дашборды смотрят люди без маркетингового бэкграунда. Возле КАЖДОГО
названия метрики, канала или аббревиатуры — значок (i) с лаконичным
объяснением на простом языке: что это и о чём говорит.
- Тексты — только в `src/lib/i18n/metric-glossary.ts` (uk/ru/en),

- Компонент: `InfoHint` (`src/components/ui/InfoHint.tsx`) — hover и focus.
- `KpiTile`/`GroupHeader` принимают проп `hint`.
- Новая метрика без записи в глоссарии = баг.

## 9c. Тактильные взаимодействия (стеклянные контролы)

Единый физический язык (адаптация «Glass Button» P. Knoll под нашу
палитру), дозируется по размеру элемента — правило: чем больше элемент,
тем меньше движения. Тайминг общий: `--press-time: 400ms`,
`--press-ease: cubic-bezier(0.25, 1, 0.5, 1)`.

| Элемент | Класс | Hover | Нажатие |
|---|---|---|---|
| Кнопки, дропдауны | `.glass-btn` | сжатие 2,5% + блик скользит | наклон-«клавиша» 12° + вдавленная тень |
| Чипы в сегмент-контролах (вкладки, языки) | `.glass-btn glass-btn-flat` | то же, но без теней в покое | то же |
| Малые плитки KPI | `.tile-press` (вместе с `.kpi-tile`) | лёгкое «нажатие»: наклон 2,5° + сжатие 1% | — |
| Большие блоки/таблицы | `.glass-card` | только тень+кромка («press-light»), БЕЗ transform | — |

Запреты:
- Наклон/scale на больших блоках с таблицами — цифры искажаются.
- transform на контейнерах с тултипами `position: fixed` без портала.
- Новые тайминги/easing — только общие `--press-*` токены.
- `prefers-reduced-motion` уже учтён в globals.css — не ломать.

## 10. Локализация

## 9d. Сортировка таблиц (обязательно)

Каждая таблица использует `useSort` + `SortableTh`
(`src/components/ui/SortableTh.tsx`): клик по колонке — сортировка ↓,
второй клик — ↑, переключение колонки начинает с ↓. Пустые значения
(«—», null) всегда в конце. В таблицах с группами (band-paid/band-free)
сортировка действует внутри групп, полосы и подытоги не двигаются.
Новая таблица без SortableTh = баг.


## Правила честности чисел (обязательны для ЛЮБОЙ новой метрики — аудит 2026-08-08)

1. **Коэффициенты только из сумм**: CTR/CPC/CPA/ROAS/CR/частота считаются из
   просуммированных числителей и знаменателей, никогда — средним по строкам/дням.
2. **Уникальные значения не суммируются молча**: охват/уникальные пользователи,
   сложенные по дням, подписываются «≈» и объясняются в глоссарии.
3. **«—» вместо нуля**: если данных нет или метрика неприменима (ROAS без
   продаж, CPA без конверсий) — показываем «—» без цвета, не «0» и не красное.
4. **Сравнение периодов**: окна одинаковой длины, смежные, без пересечений
   (учитывать лаги источников — GSC −3 дня); Δ показывается только при ≥70%
   покрытия предыдущего окна; prev-коэффициенты — из prev-сырых значений.
5. **Идентичность строк**: ключ агрегации — id (не имя); в multi-account merge
   ключ обязательно включает accountKey.
6. **Обрезка объявляется**: любой топ-N в таблице подписывается «Показаны N из M».
7. **Загрузка ≠ пусто ≠ ошибка**: три разных состояния; «Не подключено» во
   время загрузки запрещено.
8. **Пустой файл ≠ данные**: hasData проверяет наличие строк, а не файла.
9. Новые правила фиксируются здесь + сторожевым тестом в
   `tests/honesty-invariants.test.ts`.


### Мобильные таблицы: закреплённая первая колонка

На экранах <1024px первая ячейка КАЖДОЙ строки таблицы внутри `.overflow-x-auto`
закрепляется слева (sticky) с непрозрачным фоном и разделительной линией
в 1 px (мягкая полоса-«подсвет» запрещена: она читается как декоративный
акцент, а не как граница). Контракт покрывает
**thead, tbody И tfoot** — итоговая строка обязана держать подпись «Итого» на
месте при горизонтальной прокрутке (регресс 2026-08-08: tfoot не был включён в
селекторы, «Итого» уезжало, цифры плыли под закреплённой колонкой). Любая новая
таблица получает это поведение автоматически из globals.css — НЕ переопределять
локально и НЕ строить таблицы вне `.overflow-x-auto`.
